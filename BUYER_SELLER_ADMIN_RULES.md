# Bzead — Buyer · Seller · Admin Rules

> Every rule below is taken **directly from the codebase or database** (no assumptions).  
> File references use `path#Lline` so each rule can be verified.  
> Generated by auditing `Bzeadstore-main/` + Supabase migrations.

---

## 0 — Shared Concepts (read this first)

- **Three roles only:** `user` (buyer), `seller`, `admin`.  
  Stored in Supabase auth metadata + `profiles.role`. Resolved in this order: `user_metadata.role` → `app_metadata.role` → defaults to `user`. — [src/contexts/AuthContext.tsx](Bzeadstore-main/src/contexts/AuthContext.tsx#L38-L43)
- **Country table** `countries(id, country_name, short_code, currency_code, dialing_code, iso2, is_active)` drives currency, dialing codes, and shipping routing everywhere.
- **Two shipping providers:** **Shiprocket** (India origin) and **Shippo** (UK / non‑India origin).
- **Payments:** Stripe `PaymentElement` only. Amount is converted with `toStripeAmount()` before sending. — [src/lib/stripeService.ts](Bzeadstore-main/src/lib/stripeService.ts#L168-L185)
- **Order placement is one RPC:** `create_order_secure(...)`. Prices are never sent from the client — the DB recomputes them. — [src/contexts/CartContext.tsx](Bzeadstore-main/src/contexts/CartContext.tsx#L399-L430)
- **Two SKU formats:**
  - Product SKU = `BZD…` (e.g. `BZD032610001`), auto‑generated by `generateNextSku()`. — [src/lib/productService.ts](Bzeadstore-main/src/lib/productService.ts#L1053)
  - Variant SKU = `VR…` (e.g. `VR022403001`), auto‑generated, read‑only in seller UI. — [src/pages/seller/steps/ProductDetailsStep.tsx](Bzeadstore-main/src/pages/seller/steps/ProductDetailsStep.tsx#L323)

## 1 — BUYER

### 1.1 Signup & Profile
- **Fields collected:** email, password, full name, phone, optional country. Saved to `profiles`. — [src/contexts/AuthContext.tsx](Bzeadstore-main/src/contexts/AuthContext.tsx#L25)
- **Country resolution order on every page:**
  1. Shipping address country (if any address chosen)
  2. Detected country in `localStorage.beauzead_detected_location` (geolocation)
  3. `profiles.country_id`
  4. Safe fallback — [src/pages/user/Checkout.tsx](Bzeadstore-main/src/pages/user/Checkout.tsx#L168-L190)
- **Email OTP verification** is required after signup (`purpose: 'buyer-otp'`).

### 1.2 Addresses
- Saved in `user_addresses` (full_name, phone_number, street_address_1, street_address_2, city, state, postal_code, country, is_default).
- One address is always the **default** — most recently added if none explicitly marked. — [src/pages/user/AddressManagement.tsx](Bzeadstore-main/src/pages/user/AddressManagement.tsx)

### 1.3 Cart
- Persisted in Supabase table `cart_items(user_id, product_id, variant_info, quantity)` + React `CartContext`. — [src/contexts/CartContext.tsx](Bzeadstore-main/src/contexts/CartContext.tsx)
- **Variant rule (recently hardened):** for products with **more than one variant**, the cart never sends the parent `BZD…` SKU to the order. If no variant was resolved, it sends `null`. This prevents the parent SKU from polluting `order_items.variant_info.sku`. — [src/contexts/CartContext.tsx](Bzeadstore-main/src/contexts/CartContext.tsx#L405-L420)
- **Product Detail Page** auto‑resolves a variant even when there is no size/color picker (legacy variants with empty metadata) — it picks the first variant that has a real SKU. — [src/pages/ProductDetailsPage.tsx](Bzeadstore-main/src/pages/ProductDetailsPage.tsx#L411-L443)

### 1.4 Checkout & Pricing
- All checkout numbers come from `calculateDestinationCheckoutPricing(items, destination_country, buyer_currency)`. — [src/lib/checkoutPricingService.ts](Bzeadstore-main/src/lib/checkoutPricingService.ts#L1-L100)
- Output includes: `subtotal`, `offerDiscount`, `platformHandlingCharge`, `shipping`, `total`, `ineligibleItems`, `intlShippingOptions`, `minimumOrderConstraint`.
- **Minimum order rules** come from `checkout_min_order_rules(origin_country, destination_country, minimum_inr)` (e.g. India → UK requires ≥ ₹2 150). — [src/lib/checkoutPricingService.ts](Bzeadstore-main/src/lib/checkoutPricingService.ts#L222)
- **Currency conversion** uses `CurrencyContext` FX rates and is applied **once per line item** (never double‑converted).
- **Tax/HSN** is taken from `category_hsn_codes` matched on the product's category slug.

### 1.5 Place Order
- One call: RPC `create_order_secure(...)`. Returns `order_id` + `order_number`.
- Items sent contain only `product_id, quantity, product_name, product_image, variant_info{ size, color, sku, hsn_code }`. The RPC looks up prices server‑side. — [src/contexts/CartContext.tsx](Bzeadstore-main/src/contexts/CartContext.tsx#L390-L430)
- Payment is confirmed via RPC `confirm_order_payment(order_id, payment_intent_id)`, which flips `orders.payment_status` to `completed`. — [src/pages/user/Checkout.tsx](Bzeadstore-main/src/pages/user/Checkout.tsx#L965)

### 1.6 Order Tracking (`/orders/:id`)
- Reads in this order: `orders` row → `order_items` → `order_status_history` → shipment rows.
- **Shipment source is auto‑detected:**
  - If any `shiprocket_shipments` row exists for the order → carrier = Shiprocket, events from `shiprocket_tracking_events`.
  - Else if any `shippo_shipments` exists → carrier = Shippo, events from `shippo_tracking_events`, tracking URL taken from `raw_payload.tracking_url_provider`. — [src/pages/user/OrderDetails.tsx](Bzeadstore-main/src/pages/user/OrderDetails.tsx#L380-L480)
- **Expected delivery date** is taken from `orders.expected_delivery_date` first, else from the shipping address snapshot, else recomputed via `fetchMultiSellerTat(...)`. — [src/pages/user/OrderDetails.tsx](Bzeadstore-main/src/pages/user/OrderDetails.tsx#L490-L520)
- **Status History panel** renders one row per `order_status_history` entry (date + status + note).
- **Rule — no role attribution to buyers:** the Status History view strips any legacy `"by admin"` / `"updated by admin"` substrings from notes before display, and admin actions are recorded with a role‑neutral note `"Order moved to <status>"`. — [src/pages/user/OrderDetails.tsx](Bzeadstore-main/src/pages/user/OrderDetails.tsx#L1198-L1226), [src/pages/admin/modules/OrderManagement.tsx](Bzeadstore-main/src/pages/admin/modules/OrderManagement.tsx#L410-L435)

### 1.7 Cancellation (Buyer)
- Allowed only from statuses **pending, new, processing, accepted**. — [src/lib/orderService.ts](Bzeadstore-main/src/lib/orderService.ts#L367-L380)
- Goes through RPC `cancel_order_by_user(order_id, reason)` (`SECURITY DEFINER` — ownership validated server‑side).
- Cancellation is logged in `order_cancellations` and in `order_status_history`.

### 1.8 Returns (Buyer)
- Allowed only from status **delivered**.
- Created via `requestReturn(orderId, userId, reason, description, quantity, images)` → inserts into `order_returns` and writes an `order_status_history` row with note `"Return requested: <reason>"`. — [src/lib/orderService.ts](Bzeadstore-main/src/lib/orderService.ts#L510-L550)

### 1.9 Wishlist & Reviews
- **Wishlist:** stored via `WishlistContext` with backend sync; prices on cards always shown in the buyer's destination currency.
- **Reviews:** table `reviews(order_id, product_id, user_id, rating 1–5, review_text)`. Created via `productService` — only the buyer who placed the order can review the product. — [src/lib/productService.ts](Bzeadstore-main/src/lib/productService.ts#L1292)

### 1.10 What Buyers CANNOT Do
- Approve KYC, change order status manually, see commission %, or open the admin/seller panel.

## 2 — SELLER

### 2.1 Login Page (Shared Admin/Seller)
- Page: [src/pages/seller/SellerLogin.tsx](Bzeadstore-main/src/pages/seller/SellerLogin.tsx#L40-L75).  
  After auth succeeds the page reads the resolved role:
  - `seller` → `/seller/dashboard`
  - `admin`  → `/admin`
  - `user`   → blocked with an error popup ("not a seller account").

### 2.2 Signup (Seller)
- Page: [src/pages/seller/SellerSignup.tsx](Bzeadstore-main/src/pages/seller/SellerSignup.tsx).
- **Fields collected & saved to DB:**
  - email, fullName, mobile, password
  - `countryId` (from `countries`)
  - `businessTypeId` (from `business_types`)
- **Country is mandatory** at signup. It is saved to `profiles.country_id` and to the OTP context so the post‑verification flow can finalise the seller account. — [src/pages/seller/SellerSignup.tsx](Bzeadstore-main/src/pages/seller/SellerSignup.tsx#L65-L100)
- Email OTP verification is required (`purpose: 'seller-signup'`).

### 2.3 Seller Currency (locked)
- Every page in the seller dashboard renders amounts using `useSellerDisplayCurrency()`.
- Currency resolution order:
  1. `seller_kyc.business_country` (preferred)
  2. `seller_kyc.country` (fallback)
  3. `profiles.country_id` (last resort)
- The seller currency is then derived via `resolveCurrencyFromCountry()` and **cannot be switched** by the seller. — [src/hooks/useSellerDisplayCurrency.ts](Bzeadstore-main/src/hooks/useSellerDisplayCurrency.ts#L1-L87)
- All seller views (orders, wallet, analytics, dashboard) display amounts in this single currency. Buyer‑paid currency is never shown to the seller.

### 2.4 KYC — The Master Gate
- Table: `seller_kyc`. Statuses: `pending` · `approved` · `rejected`.
- Fields captured across the KYC wizard: personal (full_name, email, phone), business (city, state, postal_code, country, PAN, GSTIN, ID type/number), bank (holder, account_number, account_type, IFSC). — [src/pages/seller/kyc/KYCStep1Personal.tsx](Bzeadstore-main/src/pages/seller/kyc/KYCStep1Personal.tsx#L60-L65), [src/pages/seller/kyc/KYCStep2Business.tsx](Bzeadstore-main/src/pages/seller/kyc/KYCStep2Business.tsx#L118-L120)
- Document uploads: JPEG, PNG, PDF, DOC/DOCX. Max 10 MB. Stored in private bucket `kyc-documents` at `<sellerId>/<docType>_<timestamp>.<ext>`. — [src/lib/kycService.ts](Bzeadstore-main/src/lib/kycService.ts#L40-L65)
- **Hard rule:** until `kyc_status = 'approved'`, the seller cannot:
  - create a warehouse — [src/pages/seller/WarehouseCreation.tsx](Bzeadstore-main/src/pages/seller/WarehouseCreation.tsx#L30-L50)
  - list products (enforced when opening Product Listing).
- Approval/rejection happens admin‑side (see §3.3) and triggers `identity_approved` / `identity_rejected` notifications.

### 2.5 Warehouse (Pickup Location) Creation
- Page: [src/pages/seller/WarehouseCreation.tsx](Bzeadstore-main/src/pages/seller/WarehouseCreation.tsx).
- Prefills city/state/postal/country from `seller_kyc`. — [src/pages/seller/WarehouseCreation.tsx](Bzeadstore-main/src/pages/seller/WarehouseCreation.tsx#L100-L115)
- **Routing rule by seller country:**
  - **Seller country = India →** warehouse type `domestic`, synced to **Shiprocket**.
  - **Seller country ≠ India (UK, etc.) →** warehouse type `international`, synced to **Shippo**. — [src/lib/shippoOpsService.ts](Bzeadstore-main/src/lib/shippoOpsService.ts), [src/lib/shiprocketOpsService.ts](Bzeadstore-main/src/lib/shiprocketOpsService.ts)
- Stored in `seller_pickup_locations(seller_id, pickup_location_name, warehouse_type, is_verified, provider, shiprocket_synced, shippo_synced, phone_verified)`.
- **A warehouse is "fully verified" only when:**
  - Domestic: `is_verified = true` AND `shiprocket_synced = true` AND `phone_verified ≥ 1`.
  - International: `is_verified = true` AND `shippo_synced = true`. — [src/pages/seller/WarehouseCreation.tsx](Bzeadstore-main/src/pages/seller/WarehouseCreation.tsx#L80-L95)

### 2.6 Product Listing (after KYC approval)
- Page: [src/pages/seller/SellerProductListing.tsx](Bzeadstore-main/src/pages/seller/SellerProductListing.tsx).
- **Product SKU** auto‑generates as `BZD032610XXX` if seller doesn't supply one. — [src/lib/productService.ts](Bzeadstore-main/src/lib/productService.ts#L1053)
- **Pricing columns saved:** `price` (selling price), `mrp`, optional `discount_price`, `currency`, `origin_country`. — [src/lib/productService.ts](Bzeadstore-main/src/lib/productService.ts#L630-L650)
- **Country‑specific pricing:** sellers can override price per destination via `product_country_selling_prices(product_id, country_id, selling_price)`.
- **Approval gate:** new products start with `approval_status = 'draft'/'pending'` and only become buyer‑visible after admin marks `approved`. — [src/pages/admin/modules/ProductManagement.tsx](Bzeadstore-main/src/pages/admin/modules/ProductManagement.tsx)

### 2.7 Variants
- Stored in `product_variants(product_id, variant_type, sku, size_value, color, mrp, …)`.
- `variant_type` is `'size' | 'color' | 'combination'`.
- **Variant SKU** is auto‑generated as `VR<6digits><3digit-index>` and the input is `readOnly` in the seller UI. — [src/pages/seller/steps/ProductDetailsStep.tsx](Bzeadstore-main/src/pages/seller/steps/ProductDetailsStep.tsx#L323), [#L678](Bzeadstore-main/src/pages/seller/steps/ProductDetailsStep.tsx#L678)
- Size presets per category come from [src/config/variantThemeConfig.ts](Bzeadstore-main/src/config/variantThemeConfig.ts) (apparel XS–5XL; shoes UK/US/EU/JP; kids age ranges).
- **Validation:** every size×color combination must have a unique SKU. — [src/lib/productService.ts](Bzeadstore-main/src/lib/productService.ts#L690-L700)

### 2.8 Bulk Upload
- Key enforced rules:
  - `origin_country` = `"India"`.
  - `item_condition` = `"brand_new"`.
  - `sku` empty (system auto‑generates `BZD…`).
  - `stock` = 25.
  - `short_description` = 300–349 chars.
  - `description` = 10–15 bullet points (2–3 lines each).
  - `category_slug`, `sub_category_slug`, `product_type_slug` must match DB so HSN auto‑applies.
  - `images: []` (uploaded separately).
  - `special_day_offers_json: []`, `quantity_offers_json: []`.

### 2.9 Orders Page (Seller)
- Page: [src/pages/seller/SellerOrderManagement.tsx](Bzeadstore-main/src/pages/seller/SellerOrderManagement.tsx).
- Seller only sees orders containing their own products. Pricing shown via `resolveSellerUnitPrice / resolveSellerLineTotal` (always in seller currency).
- **Allowed status transitions (seller‑side):**
  - `pending / new / processing / accepted` → `packed`
  - `packed` → `in_transit` or `shipped`
  - `delivered` → `return_requested` (only when buyer initiates)  
  — [src/lib/orderService.ts](Bzeadstore-main/src/lib/orderService.ts#L302-L315)
- Every transition is logged via `recordStatusChange(...)` into `order_status_history` with `role = 'seller'` and note `"Seller moved order to <label>"`. — [src/pages/seller/SellerOrderManagement.tsx](Bzeadstore-main/src/pages/seller/SellerOrderManagement.tsx#L951)
- **Seller cancellation rights:** `pending, new, processing, accepted, packed` only. — [src/lib/orderService.ts](Bzeadstore-main/src/lib/orderService.ts#L368)
- For non‑Shiprocket / non‑Shippo capable sellers, the UI shows: *"Shipment will be created by admin."* — [src/pages/seller/SellerOrderManagement.tsx](Bzeadstore-main/src/pages/seller/SellerOrderManagement.tsx#L1347), [#L1418](Bzeadstore-main/src/pages/seller/SellerOrderManagement.tsx#L1418), [#L1452](Bzeadstore-main/src/pages/seller/SellerOrderManagement.tsx#L1452)

### 2.10 Wallet & Payouts
- Balance read via RPC `get_seller_wallet_balance(seller_id)`. — [src/lib/orderService.ts](Bzeadstore-main/src/lib/orderService.ts#L885)
- Withdrawal via RPC `request_withdrawal_secure(seller_id, amount, mode, account_info)`. Modes used in code: `bank_transfer`, `upi`. — [src/lib/orderService.ts](Bzeadstore-main/src/lib/orderService.ts#L730)
- Platform commission rate stored in `platform_commission_rules(country_id, from_price, to_price, charge_percent, extra_charge)`. Default = 3 % of product subtotal. — [src/lib/checkoutPricingService.ts](Bzeadstore-main/src/lib/checkoutPricingService.ts#L107)

### 2.11 Promotions
- Two types saved per product: `special_day_offers` and `quantity_offers`.
- Fields: `discount_percent`, `bundle_min_qty`, `bundle_discount`, `start_time`, `end_time`. — [src/lib/productService.ts](Bzeadstore-main/src/lib/productService.ts#L755-L770)

### 2.12 Notifications (seller‑only types)
- `identity_approved`, `identity_rejected`, `identity_pending`
- `product_approved`, `product_rejected`
- `payout_completed`, `payout_failed`  
Buyers never receive these. — [src/lib/notificationService.ts](Bzeadstore-main/src/lib/notificationService.ts#L57-L65)

### 2.13 What Sellers CANNOT Do
- Approve their own KYC, see buyer‑paid currency, touch another seller's orders, or open the admin panel.

## 3 — ADMIN

### 3.1 Login & Access
- Admins log in through the same Seller/Admin login page; the role check redirects them to `/admin`. — [src/pages/seller/SellerLogin.tsx](Bzeadstore-main/src/pages/seller/SellerLogin.tsx#L40-L75)
- Admin role is granted via RPC `admin_update_admin_role(...)` exposed in `adminService.updateAdminRole()`. — [src/pages/admin/modules/AdminManagement.tsx](Bzeadstore-main/src/pages/admin/modules/AdminManagement.tsx#L60)

### 3.2 Admin Modules (under [src/pages/admin/modules/](Bzeadstore-main/src/pages/admin/modules/))

### 3.3 Seller KYC Approval
- Page: [src/pages/admin/modules/SellerKYCSubmissionManagement.tsx](Bzeadstore-main/src/pages/admin/modules/SellerKYCSubmissionManagement.tsx).
- Filters: All / Pending / Approved / Rejected. Actions: Approve, Reject (with reason), Edit, Delete.
- **Approve:** sets `seller_kyc.kyc_status = 'approved'` and `profiles.is_verified = true`, `profiles.approved = true`. — [src/lib/kycService.ts](Bzeadstore-main/src/lib/kycService.ts#L530-L545)
- **Reject:** sets `kyc_status = 'rejected'`, stores reason. — [src/lib/kycService.ts](Bzeadstore-main/src/lib/kycService.ts#L555-L575)

### 3.4 Order Management
- Page: [src/pages/admin/modules/OrderManagement.tsx](Bzeadstore-main/src/pages/admin/modules/OrderManagement.tsx).
- Admin sees **all** orders. Operations:
  - Change status (with `VALID_TRANSITIONS` enforcement).
  - Create Shiprocket domestic / international shipments, create Shippo international shipments.
  - Generate Shiprocket label & manifest; cancel shipments.
  - NDR actions: `ndrReattempt`, `ndrReturnToOrigin`.
  - Approve / reject return requests; refund Shippo shipments; create Shippo return labels.
- **Admin cancellation rights:** `pending, new, processing, accepted, packed, in_transit, out_for_delivery` — broader than seller. — [src/lib/orderService.ts](Bzeadstore-main/src/lib/orderService.ts#L369)
- **Status history rule:** every admin status change writes to `order_status_history` with `role='admin'` and a role‑neutral note `"Order moved to <status>"`. **Never** "Updated by admin." — [src/pages/admin/modules/OrderManagement.tsx](Bzeadstore-main/src/pages/admin/modules/OrderManagement.tsx#L410-L435)
- **Buyer notification rule:** message sent to buyer says `"Your order status has been updated to X."` Never "by admin". Return titles are `"Return Approved"` / `"Return Rejected"` (no "by Admin"). — [src/pages/admin/modules/OrderManagement.tsx](Bzeadstore-main/src/pages/admin/modules/OrderManagement.tsx#L429), [#L496](Bzeadstore-main/src/pages/admin/modules/OrderManagement.tsx#L496)

### 3.5 Product Management
- Page: [src/pages/admin/modules/ProductManagement.tsx](Bzeadstore-main/src/pages/admin/modules/ProductManagement.tsx).
- Admin can approve/reject seller products (`approval_status`), edit `product_country_selling_prices`, manage categories and HSN codes.

### 3.6 Seller, Account, Banner, Category, Reports
- `SellerManagement` — list sellers, filter by KYC, change badge via `admin_update_seller_badge`. — [src/lib/adminService.ts](Bzeadstore-main/src/lib/adminService.ts#L71-L95)
- `AccountsManagement` — view all users + sellers, view their orders.
- `BannerManagement`, `CategoryManagement`, `ReportsManagement` — platform content + analytics.
- `ShippingManagementPage` — country routing config (`intl_shipping_country_config`), rate cards (`intl_rate_card`), minimum order rules (`checkout_min_order_rules`).

### 3.7 Notifications from Admin Actions
- `notifyOrderEvent({ type, orderId, ..., buyerId, sellerIds, adminNotify })` fans out one event to in‑app `notifications`, OneSignal push, and email. — [src/lib/notificationService.ts](Bzeadstore-main/src/lib/notificationService.ts#L476-L590)
- Admin actions toggle `adminNotify: true` when admins themselves need to see the event (e.g. buyer cancellation).

## 4 — Shipping Routing (decision tree)

| Seller origin | Destination | Provider | Service used |
|---|---|---|---|
| India | India | Shiprocket | Shiprocket Domestic |
| India | Any non‑India | Shiprocket | Shiprocket International |
| UK (or any non‑India) | Any | Shippo | Shippo API |

- Routing helpers: `getShippingProvider(sellerCountry, destinationCountry)` and `intl_shipping_country_config` table. — [src/pages/admin/modules/OrderManagement.tsx](Bzeadstore-main/src/pages/admin/modules/OrderManagement.tsx#L30-L35), [src/lib/shippoOpsService.ts](Bzeadstore-main/src/lib/shippoOpsService.ts#L275)
- TAT: `fetchMultiSellerTat(productIds, destinationPin, userId)` — used both at checkout and on order details for ETD fallback.

## 5 — Order Status State Machine

Allowed transitions (from `VALID_TRANSITIONS` in [src/lib/orderService.ts](Bzeadstore-main/src/lib/orderService.ts#L302-L315)):

```
pending          → accepted | cancelled
new              → accepted | cancelled
processing       → accepted | cancelled
accepted         → packed   | cancelled
packed           → in_transit | shipped | cancelled
shipped          → in_transit
in_transit       → out_for_delivery
out_for_delivery → (terminal — wait for webhook)
delivered        → return_requested
return_requested → returned | delivered
returned         → refunded
cancelled        → (terminal)
refunded         → (terminal)
```

Concurrency guard: every admin/seller status update uses `eq('status', fromStatus)` as an atomic CAS so two admins cannot race. — [src/lib/orderService.ts](Bzeadstore-main/src/lib/orderService.ts#L350-L365)

Cancellation rights by role:

| Role | Allowed `from` statuses |
|---|---|
| Buyer | `pending, new, processing, accepted` |
| Seller | `pending, new, processing, accepted, packed` |
| Admin | `pending, new, processing, accepted, packed, in_transit, out_for_delivery` |

— [src/lib/orderService.ts](Bzeadstore-main/src/lib/orderService.ts#L367-L380)

## 8 — Hard Rules (must never be broken)

1. **Buyers never see role attribution.** No "by admin", no "Updated by admin", no admin/seller names in order tracking or notifications. — [src/pages/admin/modules/OrderManagement.tsx](Bzeadstore-main/src/pages/admin/modules/OrderManagement.tsx#L410-L435), [src/pages/user/OrderDetails.tsx](Bzeadstore-main/src/pages/user/OrderDetails.tsx#L1198-L1226)
2. **Seller currency is locked** to the country in `seller_kyc`. No selector. — [src/hooks/useSellerDisplayCurrency.ts](Bzeadstore-main/src/hooks/useSellerDisplayCurrency.ts)
3. **No product listing or warehouse before KYC = approved.** — [src/pages/seller/WarehouseCreation.tsx](Bzeadstore-main/src/pages/seller/WarehouseCreation.tsx#L30-L50)
4. **India seller → Shiprocket. Non‑India seller → Shippo.** Decided when the warehouse is created and when shipments are generated.
5. **Multi‑variant products never send the parent `BZD…` SKU into `order_items.variant_info.sku`.** Cart sends `null` when no variant resolved. — [src/contexts/CartContext.tsx](Bzeadstore-main/src/contexts/CartContext.tsx#L405-L420)
6. **Variant SKU input is read‑only.** Seller cannot type it; system generates `VR…`. — [src/pages/seller/steps/ProductDetailsStep.tsx](Bzeadstore-main/src/pages/seller/steps/ProductDetailsStep.tsx#L678)
7. **Order placement uses one RPC: `create_order_secure`.** Prices are not trusted from the client.
8. **Every status change is logged** to `order_status_history` with the actor's role.
9. **Concurrent status changes are blocked** by an atomic CAS on `orders.status`. — [src/lib/orderService.ts](Bzeadstore-main/src/lib/orderService.ts#L350-L365)
10. **Buyer cancellation runs through `cancel_order_by_user`** (`SECURITY DEFINER`) — ownership is validated server‑side, not in the client.
